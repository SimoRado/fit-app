# Cubyfit pre-release privacy and legal technical audit

**Date:** 18 November 2026. **Scope:** read-only review of `C:\Fit` source, local configuration *key names/presence* (no secret values reproduced), and existing tests. This is a technical inventory for legal drafting, not a legal-compliance determination. No production traffic, dashboard settings, deployed website source, device packet capture, or production store purchase was verified.

## Executive findings

1. **High — Public privacy choices are incomplete.** Android interstitial requests are gated on UMP `canRequestAds`, but the only UI that opens the privacy-options form is an internal testing screen. No ordinary account/settings entry point exposes it when UMP requires one. The actual regional message and vendor configuration are dashboard facts. See `src/app/admob-testing.tsx`, `src/app/account.tsx`, `src/services/interstitialManager.ts`.
2. **High — Deletion does not cover every local and third-party artifact.** The server job covers enumerated Convex records, a matching RevenueCat customer, and Clerk; the device deletes the matching account SQLite database only after completion. Guest data, other devices until they reconnect, the shared downloaded catalog, Cloudflare gateway quota/session state, Sentry events, Google ad data, and store transaction records are outside that job. Do not promise immediate universal erasure. See `convex/accountDeletion.ts`, `convex/accountDeletionActions.ts`, `src/app/_layout.tsx`, `src/data/foodCatalog.ts`.
3. **High — Website and release configuration need verification.** This repository contains a standalone HTML design prototype with Google Fonts requests, but no Vercel website source/configuration. The public `cubyfit.app` pages could not be retrieved in this audit. The deployed site's font requests, legal pages, cookies, analytics, headers, and deletion page cannot be inferred from that prototype.
4. **Medium — Other services transmit data independently of ad consent.** Clerk and Convex providers mount at launch; Sentry initializes when its DSN exists, before the user reaches a consent screen. RevenueCat identifies the signed-in Clerk user and fetches customer information and offerings without using the cloud-backup or UMP switch. These need accurate disclosure and a region-specific legal-basis/consent decision; UMP controls ad requests, not those SDKs. See `src/app/_layout.tsx`, `src/core/monitoring.ts`, `src/state/subscriptions.tsx`.
5. **Medium — Signup legal acceptance lacks a readable link.** If Clerk requires `legal_accepted`, the UI shows “I accept the required terms” without linking the actual Terms or recording a document version in app code. The paywall has configurable HTTPS legal links, and `.env.local` contains both keys; their destinations/content were not validated. See `src/app/(auth)/verify-email.tsx`, `src/ui/Paywall.tsx`.

## Fonts and website

* `src/ui/fonts.tsx` loads eight `require('../../assets/fonts/*.ttf')` files through `expo-font`: Bricolage Grotesque 700/800, Figtree 400/500/600/700 and IBM Plex Sans Arabic regular/bold. No `@expo-google-fonts/*` dependency or runtime `fonts.googleapis.com` request appears in mobile source. These local assets may originate from Google Fonts, but an Expo font package or bundled TTF is **not** a runtime request to Google. `src/ui/theme.ts` maps their runtime names; `mono` currently maps to bundled Figtree semibold, not a remote font.
* Other tracked local TTFs are Big Shoulders 800/900, variable Bricolage/Figtree, Instrument Sans regular/bold, JetBrains Mono 600; the current mobile font loader does not use them. Their corresponding OFL license text files are under `assets/fonts/`. Check the precise license metadata and retain copyright/OFL notices when redistributing or self-hosting; avoid renaming modified fonts contrary to any Reserved Font Name terms.
* `Fitness × Personal Growth.html:4-6` explicitly preconnects to `fonts.googleapis.com` / `fonts.gstatic.com` and loads Big Shoulders Display, Instrument Sans, JetBrains Mono and IBM Plex Sans Arabic via Google CSS. This is a **local prototype**, not evidence that the deployed Vercel site uses it. If deployed, it causes browser-to-Google font requests. To remove those requests, place the actual licensed WOFF2 font subsets/weights in the website's own public assets, change CSS to same-origin `@font-face` URLs and preserve family, weight and fallback metrics. Vercel can serve those static files from the existing site; test computed typography and network requests after change.
* No website source, `vercel.json`, or website package is tracked here. `EXPO_PUBLIC_PRIVACY_URL` and `EXPO_PUBLIC_TERMS_URL` are configured locally but their URLs were deliberately not printed; existence does not prove route health or content. Direct public retrieval of `https://cubyfit.app/`, `/privacy`, `/terms` failed in the available web retriever. Verify the actual Vercel project, deployment, DNS, routes, font waterfall, privacy/cookie behavior and third-party scripts separately.

## Advertising and consent implementation

* `app.config.js` embeds Android AdMob app/unit IDs in native/Expo configuration and sets `delayAppMeasurementInit: true`; the iOS app ID is Google's sample, while `src/services/adMobNative.ts` permits native ads only on Android outside Expo Go. `src/services/adUnit.ts` and build-channel flags distinguish testing from production units. Native SDK behavior before JS initialization requires a built-binary network test; config intent alone cannot prove zero pre-consent network traffic.
* `AdEligibilityBridge` marks eligibility unresolved until profile and RevenueCat customer info are ready. Any active entitlement suppresses ads even when the configured Pro ID is absent; an unresolved subscription also suppresses ads. Only signed-in free users on home/workouts in foreground prepare UMP. `InterstitialManager.prepareOnce` calls `AdsConsent.gatherConsent()`, falls back to cached status on refresh error but sets `consentStatus='unavailable'`; `initializeIfEligible` and `canRequest()` require fresh permitted status, free eligibility, and other guards. Manual test loads also require consent and an internal build/test unit. This is a fail-closed **ad loading** design in the reviewed JS path.
* UMP determines regional message/form and `canRequestAds`; code has no hardcoded country list. The app does not distinguish personalized vs nonpersonalized ad request in its own adapter. A `canRequestAds=true` value is not proof of affirmative consent for every purpose. Check published GDPR/EEA/UK/Swiss and applicable US-state messages, app association, vendors, privacy policy URL, test geography, revocation and whether ad requests are allowed after each choice in the AdMob dashboard/device.
* `showPrivacyOptions()` releases an already loaded ad, shows UMP's form and rechecks permission. Its **only UI caller** is `src/app/admob-testing.tsx:161`, itself exposed from Account only when `admobTestingEnabled`. Add a normal settings privacy-options entry when UMP says it is required, with an accessible way back after a choice. There is no independent first-run consent for Sentry/Clerk/RevenueCat in this code.
* Ad frequency timestamps are written to SQLite KV store with a 5-minute initial delay, 8-minute spacing and 3 ads per rolling day. Those controls are product pacing, not a substitute for legal consent.

## Subscriptions and purchase disclosures

* Configured local public entitlement ID is **`cubyfit_pro`** (`EXPO_PUBLIC_REVENUECAT_ENTITLEMENT_ID`); the production dashboard must match it exactly. Test key is chosen in `__DEV__`; Android/iOS platform public SDK keys are chosen otherwise. Public RevenueCat SDK keys, a Sentry DSN, Clerk publishable key and AdMob IDs are identifiers intended to ship in a client, not server secrets.
* `subscriptionPackages` recognizes `annual`, `monthly`, `weekly` from the current RevenueCat offering, but `src/ui/Paywall.tsx` offers **annual and monthly only**. Actual store **product IDs, base plans, prices, currency, trial phases, offering selection and entitlement attachment are not in source** and need RevenueCat/Google Play/App Store inspection. Do not infer live pricing or an active weekly plan from old documentation or Test Store state.
* `src/services/paywallLogic.ts` uses the store product's `priceString` for billed price; monthly equivalence for annual falls back to `price / 12` formatting if `pricePerMonthString` is absent. Android trial text depends on the offer's default free phase; iOS checks intro eligibility. Unknown eligibility does not promise a trial. The CTA, timeline and adjacent disclosure show trial length, post-trial full-period charge, recurring interval and cancellation route. Verify actual offer eligibility and date calculations on release devices; a display estimate of a renewal date is not a store guarantee.
* `src/ui/Paywall.tsx` has Restore purchases, store subscription management and HTTPS Terms/Privacy links only when configured. The benefits list implies Pro unlocks habits/progress/nutrition/workouts, while its own intro says Pro is “without ads”; verify what is genuinely exclusive and make offer copy match actual access. Check whether annual displayed per-month amount could be mistaken for the billed amount on the store screen, and ensure full-period amount remains conspicuous. Deleting the app account does not cancel the store plan.

## Account deletion and retention

* `src/app/delete-account.tsx` requires exact phrase, a Clerk email-code factor, and a freshly fetched session token; server `convex/accountDeletionActions.ts` validates matching subject/issuer and a factor verified within ten minutes. The server refuses to start if its required Clerk/RevenueCat environment keys are missing. It creates a durable job, blocks private Convex operations via `convex/security.ts`, deletes the 15 owner-indexed private tables, a RevenueCat customer (after alias checks), then Clerk identity, with retry categories and scheduled backoff. `convex/accountDeletion.ts` retains completed jobs roughly 30 days to support later local cleanup. These are **verified code paths, not proof of a successful live end-to-end deletion**.
* Client SecureStore retains a pending receipt and polls deletion status, then removes the matching account SQLite database, clears reminders and signs out. Offline devices keep their local files until they reconnect and process completion. Guest data and other accounts are intentionally separate; downloaded catalog and shared KV store survive. `ACCOUNT_DELETION_SECURITY.md` explicitly says no disposable-account end-to-end deletion had been run at its writing; the user's description of a later tested flow does not supply test evidence in this repository. Re-run with disposable accounts and inspect Convex/RevenueCat/Clerk plus reconnecting devices before publishing a deletion promise.
* No code purges Sentry events, Google/UMP ad records, Cloudflare quota/session state, store records, provider backups or OS backup copies. Define deletion/retention schedules, legal exceptions, processors, and support escalation for shared RevenueCat aliases or failed stages. A website request path is required for Google Play's account-deletion listing; its current existence and usability were not verified. The app should explain what happens to an active subscription and to offline/guest copies.

## Security and logging

* `.env.local` is ignored by Git; server-side Clerk/RevenueCat deletion secrets are read from Convex `process.env`, not `EXPO_PUBLIC_`. The reviewed tracked text contained no matches for common literal `sk_test_`/`sk_live_` keys or PEM private-key headers. This narrow scan cannot establish absence of all credentials in historical commits, binaries, EAS variables or generated bundles. Do not place `SENTRY_AUTH_TOKEN`, Clerk secret, RevenueCat secret or R2 credentials in `EXPO_PUBLIC_` or Expo `extra`.
* `src/core/monitoring.ts` sends no default PII and removes broad event fields before sending, but SDK/device metadata and stack traces need a real captured-event review. `src/core/runtime.ts` auth diagnostics and `src/services/adMob.ts` events log only in `__DEV__`; `src/ui/Paywall.tsx` logs offering/product IDs and pricing in `__DEV__`; `src/data/syncLocal.ts` warns with kind/action and first eight operation-ID characters, not payload. Error UI in other code should still be checked against real provider messages. No statement that logging is completely free of personal data is justified without a release log/Sentry inspection.
* Expo's public variables and config-extra values are bundle-visible by design. Source review shows public IDs/URLs and a Sentry DSN used as such; inspect an actual release export/APK for unexpected environment leakage, especially since local build processes read `.env.local`.
