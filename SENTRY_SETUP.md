4. In a development build, open the Premium Test screen and tap **Send handled Sentry test event**. Verify it appears in the development Sentry project with `environment=development` and `area=developer-test`. This test does not crash the app. Verify a separate real handled failure only when safe to reproduce.
5. A standalone Android JavaScript export with an external source map was uploaded to the `fit-app` Sentry project. Sentry lists upload ID `976f1d6d-73e1-539a-85c5-5ed712339862` with two files. The Windows `sentry-expo-upload-sourcemaps` wrapper could not launch its extensionless CLI executable, so the equivalent `sentry-cli.cmd sourcemaps upload --debug-id-reference <bundle> <map>` command was used. This confirms upload, not on-device symbolication. The development APK build log has no source-map upload step because the development client loads JavaScript from Metro. A future preview/release build with an embedded bundle is needed for release stack verification.
6. A command-line transport test reached the correct Sentry project with a development environment tag. It did not exercise the mobile SDK. The CLI unexpectedly added workstation metadata. The single test issue `FIT-APP-1` was deleted with the user's authorization and Sentry showed **Issue deleted**. Do not use the CLI command for privacy testing; use the app's guarded test button on a connected device. The mobile SDK's `beforeSend` removes user and context fields. As of this verification, no Android device was connected through ADB and the app test button had not been pressed.

## Convex development deployment

Convex exception reporting is a dashboard integration, available on Convex Pro. The existing development deployment `greedy-scorpion-117` currently shows the Sentry integration behind a **PRO** requirement, so it was not enabled. If the team upgrades, create a separate Sentry project with platform **Node.js**. In the **existing development deployment** only, open **Deployment Settings → Integrations → Sentry**, enter that backend project's DSN, and add a tag such as `service=convex`. Do not select the production deployment. Convex automatically includes deployment environment, function name and type, request ID, and authenticated token identifier. Review function exception messages before enabling the integration because Convex does not provide the mobile SDK's event sanitizer.

After connecting, trigger a controlled development-only failing function only with appropriate deployment access, then confirm the event arrives in the backend Sentry project. The mobile test button does not test Convex reporting.

Sources: [Expo Sentry guide](https://docs.expo.dev/guides/using-sentry/), [Convex exception reporting](https://docs.convex.dev/production/integrations/exception-reporting).
